왜 Presigned URL인가 #

서버를 거쳐서 파일을 업로드하면 서버의 메모리와 대역폭을 잡아먹는다. 특히 이미지처럼 큰 파일은 서버에 부담이 크다. Presigned URL을 쓰면 클라이언트가 S3에 직접 업로드하기 때문에 서버는 URL만 발급하면 된다. 서버 부하가 확 줄어든다.

Presigned URL은 서버의 부하를 줄이면서도 보안을 유지하는 좋은 방법이다. 단, 만료 시간 설정에 주의해야 한다.

업로드 흐름 #

흐름은 이렇다. 클라이언트가 서버에 "업로드할 거야"라고 요청하면, 서버가 S3에 접근할 수 있는 임시 URL을 만들어서 돌려준다. 클라이언트는 그 URL로 S3에 직접 파일을 올린다. 서버는 파일 데이터를 한 바이트도 만지지 않는다.

Presigned URL 업로드 흐름

이 방식의 장점을 정리하면:

  • 서버 메모리 절약 — 파일이 서버를 거치지 않음
  • 서버 대역폭 절약 — S3가 직접 수신
  • 확장성 — 업로드 수가 늘어도 서버 부하 없음

S3 설정 #

S3Client 빈 등록 #

먼저 S3Client를 빈으로 등록해야 한다. AWS SDK v2를 사용한다. application.yml에서 키와 리전 정보를 읽어오고, StaticCredentialsProvider로 인증을 처리한다.

@Configuration
@RequiredArgsConstructor
public class S3Config {
    private final AwsS3Properties awsS3Properties;

    @Bean
    public S3Client s3Client() {
        return S3Client.builder()
                .region(Region.of(awsS3Properties.getRegion()))
                .credentialsProvider(credentialsProvider())
                .build();
    }

    private StaticCredentialsProvider credentialsProvider() {
        return StaticCredentialsProvider.create(
                AwsBasicCredentials.create(
                        awsS3Properties.getAccessKey(),
                        awsS3Properties.getSecretKey()));
    }
}

Properties 바인딩 #

설정값은 @ConfigurationProperties로 바인딩한다. Java 16의 Record를 쓰면 불변 객체를 깔끔하게 만들 수 있다. @Validated를 붙여서 필수값 누락을 앱 시작 시점에 잡아낸다.

@Validated
@ConfigurationProperties(prefix = "aws.s3")
public record AwsS3Properties(
        @NotBlank String accessKey,
        @NotBlank String secretKey,
        @NotBlank String region,
        @NotBlank String bucket,
        @Positive Long presignedUrlExpiration
) { }

Record는 Java 16부터 정식 지원된다. 불변 데이터 객체를 만들 때 보일러플레이트 코드를 대폭 줄여준다.

YAML 설정 #

aws:
  s3:
    access-key: ${AWS_ACCESS_KEY}
    secret-key: ${AWS_SECRET_KEY}
    region: ap-northeast-2
    bucket: my-bucket
    presigned-url-expiration: 3600

spring:
  datasource:
    url: jdbc:postgresql://localhost:5432/mydb
    username: admin
    password: ${DB_PASSWORD}

주의할 점 #

Presigned URL에는 만료 시간이 있다. 너무 짧으면 사용자가 업로드하기 전에 만료되고, 너무 길면 보안 위험이 생긴다. 보통 5분에서 15분 사이가 적당하다. 우리 프로젝트에서는 presigned-url-expiration 값을 3600초(1시간)로 잡았는데, 실서비스에서는 줄이는 게 좋다.

또 하나, CORS 설정을 빼먹으면 브라우저에서 직접 업로드할 때 막힌다. S3 버킷의 CORS 정책에 프론트엔드 도메인을 허용해줘야 한다. 이거 빼먹고 "왜 안 되지?" 하면서 한 시간 날린 적이 있다.

CORS 미설정 시 발생하는 에러

CORS 설정은 프론트엔드와 백엔드 간의 보안 정책이다. 다른 도메인에서 오는 요청을 허용하려면 명시적으로 설정해야 한다.

정리 #

Presigned URL을 쓰면 파일 업로드의 책임을 서버에서 클라이언트로 옮길 수 있다. 서버는 URL 발급만 담당하고, 실제 파일 전송은 클라이언트와 S3 사이에서 직접 이루어진다. Spring Boot와 AWS SDK v2를 쓰면 구현도 간단하다.
